### 1.2 各层详细设计

#### L1 感知/网关层：多源数据统一接入

**设计目标**：将用户分散在微信、QQ、智能手表等终端的碎片化信息，统一接入负熵引擎，进行初步结构化、去噪和隐私保护。

**核心组件**:

| 组件 | 开源基础 | 自研增强 | 职责 |
|------|---------|---------|------|
| 消息网关 | Hermes `gateway/run.py` | 微信/QQ/手表适配器 | 统一协议转换，将各平台消息转为内部 `MessageEvent` |
| 数据清洗器 | — | **自研** | 去重、去噪、格式化、分词预处理 |
| 隐私脱敏器 | — | **自研** | PII识别与脱敏（基于正则+模型），敏感信息本地化存储 |
| 熵增预检器 | — | **自研** | 计算输入信息的信息熵，标记高熵（混乱度）内容 |
| 多模态解析器 | Hermes 工具链 | 语音/图片专用解析 | 语音转文本、图片OCR、视频摘要 |

**数据模型 `MessageEvent`**:
```python
class MessageEvent:
    source: str           # "wechat" | "qq" | "watch" | "web"
    user_id: str          # 统一用户标识（哈希化）
    timestamp: datetime
    content_type: str     # "text" | "voice" | "image" | "file" | "location"
    raw_content: str      # 原始内容
    cleaned_content: str  # 清洗后内容
    entropy_score: float  # 信息熵分数 [0, 1]
    pii_flag: bool        # 是否含敏感信息
    topic_hint: str       # 预分类标签（工作/学习/生活/待办）
```

**关键自研点**：
- **信息熵预检算法**：基于词频分布计算Shannon熵，快速标记碎片化/重复/无结构信息
- **跨平台用户身份统一**：将微信OpenID、QQ号、手表设备ID映射到同一`user_id`
- **本地化隐私网关**：敏感信息不上云，仅在本地做特征提取

**核心算法：决策路由算法**

```python
class EntropyRouter:
    """
    负熵引擎核心路由决策器
    基于输入信息的熵特征 + 用户历史模式，决定走认知层还是执行层
    """
    
    def route(self, message: MessageEvent, user_profile: UserModel) -> RouteDecision:
        # 维度1: 信息混乱度 (0-1)
        info_entropy = self.compute_shannon_entropy(message.cleaned_content)
        
        # 维度2: 决策复杂度 (1-10)
        # - 涉及多个变量 → 高
        # - 有明确单一目标 → 低
        decision_complexity = self.llm_classify_complexity(message, user_profile)
        
        # 维度3: 时间压力 (0-1)
        # - 紧急/ deadline → 高 → 走执行层
        time_pressure = self.extract_urgency(message)
        
        # 维度4: 历史成功率
        # - 同类问题过去走认知层的决策质量
        historical_quality = self.get_historical_quality(user_profile, message.topic_hint)
        
        # 综合评分
        cognitive_score = (
            info_entropy * 0.3 +
            decision_complexity * 0.1 +
            (1 - time_pressure) * 0.2 +
            historical_quality * 0.4
        )
        
        if cognitive_score > 0.6:
            return RouteDecision(
                target="cognitive",  # → Counsel AI私董会
                reason="高混乱度 + 低时间压力 + 历史认知决策有效",
                depth=self.select_depth(cognitive_score),
                personas=self.recommend_personas(message, user_profile)
            )
        else:
            return RouteDecision(
                target="execution",  # → Agency技能库
                reason="低混乱度/高时间压力/明确目标 → 直接执行",
                agent_pool=self.recommend_agents(message, user_profile)
            )
```

**核心算法：熵增检测器**

```python
class EntropyDetector:
    """
    信息混乱度检测器 —— 负熵引擎的"温度计"
    量化用户的日常信息输入在多大程度上处于高熵（混乱）状态
    """
    
    def compute_daily_entropy(self, day_events: List[MessageEvent]) -> DailyEntropyReport:
        # 1. 词频分布熵 (Shannon Entropy)
        text_corpus = " ".join([e.cleaned_content for e in day_events])
        word_freq = Counter(text_corpus.split())
        total = sum(word_freq.values())
        shannon_entropy = -sum((c/total) * log2(c/total) for c in word_freq.values())
        
        # 2. 主题分散度 (Topic Scatter)
        # 使用预训练分类器将每条消息分到N个主题
        topic_distribution = self.classify_topics(day_events)
        topic_entropy = self.compute_distribution_entropy(topic_distribution)
        
        # 3. 时间碎片化度 (Temporal Fragmentation)
        # 消息在时间轴上的分布均匀度 → 越均匀 = 越碎片化 = 越高熵
        timestamps = [e.timestamp for e in day_events]
        temporal_entropy = self.compute_temporal_entropy(timestamps)
        
        # 4. 跨平台切换频率 (Context Switching)
        platform_switches = sum(
            1 for i in range(1, len(day_events)) 
            if day_events[i].source != day_events[i-1].source
        )
        switch_rate = platform_switches / len(day_events)
        
        # 5. 待办/行动项密度 (Action Density)
        # 高熵状态通常伴随大量待办但无结构化
        action_items = self.extract_action_items(day_events)
        action_entropy = len(action_items) / (len(day_events) + 1)
        
        # 综合熵值 (0-1标准化)
        raw_entropy = (
            self.normalize(shannon_entropy, max_entropy=12) * 0.25 +
            topic_entropy * 0.25 +
            temporal_entropy * 0.20 +
            switch_rate * 0.15 +
            self.sigmoid(action_entropy - 0.3) * 0.15
        )
        
        return DailyEntropyReport(
            overall_score=raw_entropy,
            breakdown={
                "information_entropy": shannon_entropy,
                "topic_scatter": topic_entropy,
                "temporal_fragmentation": temporal_entropy,
                "platform_switching": switch_rate,
                "action_density": action_entropy
            },
            trend=self.compare_with_history(day_events[0].user_id, raw_entropy),
            recommendation=self.generate_recommendation(raw_entropy)
        )
```

#### L3 认知层：Counsel AI私董会 —— 认知降熵核心

**设计目标**：当用户面临高不确定性决策、信息混乱、认知困境时，启动12正交哲学框架幕僚的私董会流程，通过系统化的认知科学方法，将混乱的思绪结构化为清晰的决策路径。

**核心组件**:

| 组件 | 开源基础 | 自研增强 | 职责 |
|------|---------|---------|------|
| Facilitator | Counsel 流程守护 | 负熵专用引导Prompt | 主持8步流程，多轮对话澄清问题 |
| 12 Persona幕僚 | Counsel `personas/` | 可动态扩展为N个 | 并行独立生成观点（NGT） |
| NGT引擎 | Counsel Step 4 | **自研** 量化评估 | 名义群体法：12人同时独立发言，消除锚定 |
| Delphi引擎 | Counsel 多轮更新 | **自研** 收敛度计算 | 传递推理过程，多轮收敛 |
| 冲突提炼器 | Counsel Step 5 | **自研** 维度量化 | 从48条观点中提炼3-6个冲突维度 |
| Pre-Mortem | Counsel 失败预设 | **自研** 风险矩阵 | "已经失败了，原因是什么？" |
| Secretary | Counsel 记录归档 | **自研** 结构化输出 | 共识摘要 + 分歧 + To-Do + 贝叶斯更新 |
| 贝叶斯更新器 | Counsel 信念记录 | **自研** 量化更新公式 | Prior → Evidence → Posterior |

**8步双钻石流程（完整的认知降熵流水线）**:

```
Step 1: 输入困惑（Input）
    用户自由倾诉 → Facilitator接收原始混乱输入
    输出: raw_input.md
    
Step 2: 定义问题（Define）
    Facilitator多轮对话澄清 → 将混乱表述转化为结构化问题陈述
    输出: defined_problem.md (包含: 核心问题、边界条件、成功标准)
    
Step 3: 挖事实（Facts）
    12幕僚各提出1-2个关键事实问题 → 自动Web搜索/数据库检索 → 事实摘要
    输出: facts_summary.md
    
Step 4: 独立发言（NGT Nominal Group Technique）
    12幕僚Promise.all并行生成观点 → 互不可见（消除锚定）
    输出: 12份独立意见书 → opinions/
    
Step 5: 拆维度（Dimensions）
    Facilitator分析48条观点 → 提炼3-6个核心冲突维度
    输出: dimensions.md (每个维度: 定义、正方案、反方案、关键假设)
    
Step 6: 深度辩论（Debate）
    全体幕僚就每个维度表态 → Red Team攻击 → 正方防御
    输出: debate.md (每维度: 投票分布、最强论点、未解决争议)
    
Step 7: 汇总（Synthesis）
    Secretary生成: 共识摘要 + 未解决分歧 + 贝叶斯信念更新 + 行动建议
    输出: summary.md + bayesian_state.json
    
Step 8: 摘果子（Harvest）

    """
    量化私董会流程的认知降熵效果
    """
    
    def measure_session(self, session: CounselSession) -> CognitiveNegentropy:
        # 1. 问题清晰度提升 (Problem Clarity Gain)
        # Step 2输出 vs Step 1输入的信息熵差
        clarity_gain = entropy(session.raw_input) - entropy(session.defined_problem)
        
        # 2. 观点多样性指数 (Perspective Diversity Index)
        # 12个幕僚的立场分布 → 越分散越好（避免回声室）
        opinions = session.opinions
        stance_vectors = [self.embed(opinion.stance) for opinion in opinions]
        diversity = self.compute_cosine_diversity(stance_vectors)
        
        # 3. 冲突覆盖度 (Conflict Coverage)
        # Step 5提炼的冲突维度是否覆盖了所有关键分歧
        dimensions = session.dimensions
        coverage = self.check_opinion_coverage(dimensions, opinions)
        
        # 4. 共识收敛度 (Consensus Convergence)
        # Step 7的共识强度 vs Step 4的分歧程度
        initial_variance = self.compute_opinion_variance(opinions)
        final_consensus = self.compute_consensus_strength(session.summary)
        convergence = (initial_variance - final_consensus) / initial_variance
        
        # 5. 行动清晰度 (Action Clarity)
        # To-Do清单的可执行性评分
        action_clarity = self.evaluate_action_clarity(session.harvest.todos)
        
        return CognitiveNegentropy(
            clarity_gain=clarity_gain,
            perspective_diversity=diversity,
            conflict_coverage=coverage,
            consensus_convergence=convergence,
            action_clarity=action_clarity,
            overall_score=weighted_average([
                clarity_gain, diversity, coverage, convergence, action_clarity
            ], weights=[0.25, 0.15, 0.20, 0.25, 0.15])
        )

class TaskOrchestrator:
    """
    负熵引擎任务编排器 —— 让147个Agent自动协作
    将Counsel输出的To-Do清单转化为可执行的任务DAG
    """
    
    def create_execution_plan(self, counsel_output: CounselResponse) -> ExecutionDAG:
        # 1. 解析To-Do清单
        todos = counsel_output.todos
        
        # 2. 为每个To-Do匹配最优Agent
        task_assignments = []
        for todo in todos:
            agent = self.match_agent(todo.description, todo.category)
            task_assignments.append(TaskNode(
                id=todo.id,
                description=todo.description,
                assigned_agent=agent,
                dependencies=todo.blocked_by,
                estimated_duration=self.estimate_duration(todo, agent),
                required_tools=self.infer_tools(todo)
            ))
        
        # 3. 构建DAG（拓扑排序）
        dag = self.build_dag(task_assignments)
        
        # 4. 并行化优化（无依赖的任务并行执行）
        parallel_groups = self.compute_parallel_groups(dag)
        
        # 5. 添加质量关卡节点
        dag_with_gates = self.insert_quality_gates(dag)
        
        return ExecutionDAG(
            nodes=dag_with_gates,
            parallel_groups=parallel_groups,
            total_estimated_duration=self.sum_critical_path(dag_with_gates),
            risk_nodes=self.identify_risks(dag_with_gates)
        )
    
    def match_agent(self, task_description: str, category: str) -> AgentProfile:
        """为任务匹配最佳Agent"""
        # 方法1: 基于分类的硬匹配
        if category in AGENT_CATEGORY_MAP:
            candidates = AGENT_CATEGORY_MAP[category]
        
        # 方法2: 基于描述的Embedding相似度软匹配
        task_embedding = self.embed(task_description)
        similarities = [
            cosine_similarity(task_embedding, agent.embedding)
            for agent in ALL_AGENTS
        ]
        
        # 方法3: 历史成功率加权
        best_agent = self.weighted_select(candidates, similarities, historical_success)
        return best_agent
```

#### L7 反馈/进化层：贝叶斯飞轮

**设计目标**：形成"决策→执行→反馈→进化"的闭环，让整个系统随使用时间提升负熵效果。

**核心组件**:

| 组件 | 开源基础 | 自研增强 | 职责 |
|------|---------|---------|------|
| 贝叶斯更新器 | Counsel 信念记录 | **自研** 量化公式 | Prior + Evidence → Posterior |
| 决策审计引擎 | — | **自研** | 预期vs实际对比 |
| 路由策略学习 | Hermes 后台审查 | **自研** 强化学习 | 认知/执行路由策略进化 |
| 负熵仪表盘 | — | **自研** | 可视化熵减趋势 |
| 知识蒸馏器 | Hermes GEPA | **自研** 负熵评估集 | 成功案例→模板，失败→教训库 |

**贝叶斯飞轮公式**:

```python
class BayesianFlywheel:
    """
    负熵引擎核心反馈闭环 —— 贝叶斯信念更新
    """
    
    def update_belief(self, prior: BeliefState, evidence: DecisionOutcome) -> BeliefState:
        # 先验信念: P(H) —— 用户对该类决策的信心基线
        prior_prob = prior.confidence
        
        # 似然: P(E|H) —— 在该假设下观察到该证据的概率
        # 基于历史同类决策的成功率
        likelihood = self.compute_likelihood(prior.decision_type, evidence)
        
        # 边际概率: P(E)
        marginal = self.compute_marginal(evidence)
        
        # 后验: P(H|E) = P(E|H) * P(H) / P(E)
        posterior_prob = (likelihood * prior_prob) / marginal
        
        # 信念更新幅度（用于追踪用户判断力进化）
        update_magnitude = abs(posterior_prob - prior_prob)
        
        return BeliefState(
            confidence=posterior_prob,
            update_magnitude=update_magnitude,
            evidence_count=prior.evidence_count + 1,
            last_updated=now(),
            decision_type=prior.decision_type
        )
    
    def compute_negentropy_trend(self, user_id: str, window_days: int = 30) -> TrendReport:
        """计算用户在时间窗口内的负熵趋势"""
        daily_scores = self.query_daily_entropy(user_id, window_days)
        
        # 趋势线拟合
        slope, intercept, r_value = linregress(range(len(daily_scores)), daily_scores)
        
        # 熵减加速度
        entropy_reduction_rate = -slope  # 负斜率 = 熵在降低
        
        # 稳定性（熵值波动幅度）
        volatility = std(daily_scores)
        
        return TrendReport(
            current_avg=mean(daily_scores[-7:]),
            trend_slope=slope,
            entropy_reduction_rate=entropy_reduction_rate,
            volatility=volatility,
            forecast_7day=self.forecast(daily_scores, 7),
            recommendation=self.generate_trend_recommendation(slope, volatility)
        )
```

#### 1.4.4 负熵度量API

```python
# ============ 负熵度量API（L6/L7核心接口） ============

class NegentropyMetricsAPI:
    """
    负熵度量服务 —— 整个系统的"仪表盘"
    提供信息熵计算、熵减效果评估、趋势预测
    """
    
    # === 信息熵计算 ===
    
    @staticmethod
    def compute_shannon_entropy(text: str) -> float:
        """
        计算文本的香农信息熵
        H(X) = -Σ p(x) * log2(p(x))
        返回值越大 → 信息越混乱/越不可预测
        """
        words = text.split()
        freq = Counter(words)
        total = len(words)
        entropy = -sum((c/total) * log2(c/total) for c in freq.values())
        return entropy
    
    @staticmethod
    def compute_relative_entropy(
        source_distribution: Dict[str, float],
        target_distribution: Dict[str, float]
    ) -> float:
        """
        计算KL散度（相对熵）
        D_KL(P||Q) = Σ P(x) * log(P(x)/Q(x))
        用于度量"混乱分布"到"有序分布"的距离
        """
        kl = 0.0
        for key, p in source_distribution.items():
            q = target_distribution.get(key, 1e-10)
            kl += p * log(p / q)
        return kl
    
    # === 熵减效果评估 ===
    
    @staticmethod
    def compute_entropy_reduction(
        before_state: InformationState,
        after_state: InformationState
    ) -> EntropyReduction:
        """
        计算从"处理前"到"处理后"的熵减效果
        """
        shannon_reduction = before_state.shannon_entropy - after_state.shannon_entropy
        topic_reduction = before_state.topic_scatter - after_state.topic_scatter
        
        # 负熵值 = 熵的减少量（正值 = 有序度提升）
        negentropy = max(0, shannon_reduction + topic_reduction * 0.5)
        
        return EntropyReduction(
            shannon_reduction=shannon_reduction,
            topic_reduction=topic_reduction,
            negentropy=negentropy,
            efficiency=negentropy / (after_state.processing_cost + 1),
            quality_score=after_state.clarity * after_state.actionability
        )
    
    # === 趋势预测 ===
    
    @staticmethod
    def forecast_entropy_trend(
        historical_entropy: List[float],
        forecast_days: int
    ) -> TrendForecast:
        """
        基于历史熵值预测未来趋势
        使用简单线性回归 + 季节性调整
        """
        # 线性趋势
        x = range(len(historical_entropy))
        slope, intercept, r_value, _, _ = linregress(x, historical_entropy)
        
        # 预测
        future = [slope * (len(x) + i) + intercept for i in range(forecast_days)]
        
        # 置信区间（基于历史波动）
        std_dev = std(historical_entropy)
        
        return TrendForecast(
            predicted_values=future,
            confidence_interval_95=[(f - 1.96*std_dev, f + 1.96*std_dev) for f in future],
            trend_direction="decreasing" if slope < -0.001 else "increasing" if slope > 0.001 else "stable",
            r_squared=r_value**2
        )
    
    # === 用户负熵报告 ===
    
    @staticmethod
    def generate_user_negentropy_report(user_id: str, period: str) -> UserNegentropyReport:
        """
        生成用户在指定周期内的负熵报告
        """
        # 查询周期数据
        if period == "daily":
            data = query_last_n_days(user_id, 1)
        elif period == "weekly":
            data = query_last_n_days(user_id, 7)
        elif period == "monthly":
            data = query_last_n_days(user_id, 30)
        
        # 计算指标
        avg_entropy = mean([d.overall_score for d in data])
        trend = compute_trend([d.overall_score for d in data])
        cognitive_sessions = query_cognitive_sessions(user_id, period)
        
        return UserNegentropyReport(
            period=period,
            avg_daily_entropy=avg_entropy,
            entropy_trend=trend,
            cognitive_sessions_count=len(cognitive_sessions),
            avg_cognitive_negentropy=mean([s.overall_cognitive_score for s in cognitive_sessions]),
            top_decisions=[s.summary for s in cognitive_sessions[:3]],
            recommendations=generate_recommendations(avg_entropy, trend)
        )
```

### 1.5 "高熵增系统熵减"第一性原理落地

#### 1.5.1 理论根基：从香农信息论到负熵引擎

**核心命题**：用户的日常工作/学习/生活系统是一个**高熵增系统**——信息碎片化、注意力分散、决策混乱、行动无序。负熵引擎的目标是通过多智能体认知辅助，持续向该系统注入**负熵**（信息有序化、决策结构化、行动自动化），从而降低系统混乱度。

**第一性原理分解**：

| 理论来源 | 核心概念 | 在负熵引擎中的落地 |
|---------|---------|------------------|
| **香农信息论 (1948)** | 信息熵 H(X) = -Σ p(x)logp(x) | 量化用户日常信息的混乱度；计算处理前后的熵减 |
| **普里高津耗散结构 (1967)** | 开放系统在远离平衡态时可通过能量/信息流形成有序结构 | 负熵引擎作为"信息泵"，将用户的碎片化输入结构化为有序输出 |
| **贝叶斯决策理论** | Prior + Evidence → Posterior | 用户决策能力的持续进化；跨Session信念更新 |
| **认知负荷理论 (Sweller, 1988)** | 工作记忆容量有限，外在认知负荷需最小化 | 私董会流程将复杂决策的外部化，释放用户工作记忆 |
| **名义群体法 (NGT, Delbecq)** | 独立生成→共享→讨论→投票 | 12幕僚独立发言消除锚定效应 |
| **Delphi法 (RAND, 1962)** | 多轮匿名反馈收敛专家意见 | 跨Session的信念传递与收敛 |
| **双钻石设计模型** | 先发散（找对问题）再收敛（找好答案） | Counsel 8步流程的宏观结构 |
| **多元思维模型 (芒格)** | 80-90个重要模型跨学科应用 | 12正交哲学框架的幕僚设计 |

#### 1.5.2 负熵的量化定义

```
负熵 (Negentropy) = ΔS = S_before - S_after

其中:
- S_before: 处理前的系统熵值（信息混乱度）
- S_after: 处理后的系统熵值（信息有序度）
- ΔS > 0: 负熵成功注入（系统更有序）
- ΔS < 0: 熵增（处理反而增加了混乱）

系统熵 S 由5个子维度加权组成:
S = w1*H_information + w2*H_topic + w3*H_temporal + w4*H_platform + w5*H_action

权重建议:
w1=0.25 (信息内容混乱度)
w2=0.25 (主题分散度)
w3=0.20 (时间碎片化度)
w4=0.15 (跨平台切换度)
w5=0.15 (行动无序度)
```

**用户级负熵仪表盘指标**:

| 指标 | 定义 | 计算方式 | 目标值 |
|------|------|---------|--------|
| **日熵值** | 单日综合混乱度 | 5维加权平均 | < 0.4（低熵状态） |
| **熵减速率** | 系统有序化的速度 | -dS/dt | > 0.01/天 |
| **认知负熵** | 私董会的降熵效果 | Session前后问题清晰度差 | > 0.3 |
| **决策准确度** | 预期vs实际匹配度 | 3个月后回填评分 | > 0.7 |
| **执行完成率** | To-Do实际完成比例 | 已完成 / 总生成 | > 0.6 |
| **Skill激活率** | 自定义Skill被使用频率 | 激活次数 / 总决策数 | > 0.3 |

  4. L7反馈: 3个月后评估学习效果 → 贝叶斯更新学习策略

  → 负熵 ΔS = 0.45 ✓

class EntropyDetectorMVP:
    def compute(self, text: str) -> float:
        # 仅实现香农熵 + 简单的主题分类
        words = text.split()
        freq = Counter(words)
        total = len(words)
        entropy = -sum((c/total) * log2(c/total) for c in freq.values())
        # 归一化到0-1
        return min(entropy / 12.0, 1.0)

## 附录：术语表

| 术语 | 解释 |
|------|------|
| **负熵 (Negentropy)** | 系统有序度的度量，等于熵的减少量。负熵引擎中特指"信息混乱度降低" |
| **信息熵 (Shannon Entropy)** | 信息论中度量信息不确定性的指标，H(X) = -Σ p(x)logp(x) |
| **多智能体 (Multi-Agent)** | 由多个自主Agent组成的系统，Agent间可协作/竞争 |
| **私董会 (Counsel)** | 一种高阶决策咨询形式，由多位外部专家为案主提供多元视角 |
| **NGT (Nominal Group Technique)** | 名义群体法：先独立生成观点，再共享讨论，消除锚定效应 |
| **Delphi法** | 多轮匿名专家反馈，逐步收敛意见 |
| **Pre-Mortem** | "事前验尸"：假设项目已失败，分析原因以提前预防 |
| **贝叶斯更新** | 根据新证据更新信念概率的方法 |
| **双钻石模型** | 设计思维流程：发散→收敛→发散→收敛 |
| **SKILL.md** | Hermes/Claude Code生态的标准技能文件格式 |
| **GEPA** | Genetic-Pareto Prompt Evolution，遗传帕累托提示词进化 |
| **DAG** | Directed Acyclic Graph，有向无环图，用于任务编排 |
| **认知负荷** | 工作记忆处理信息的负担，负熵引擎旨在降低外在认知负荷 |
| **耗散结构** | 开放系统在远离平衡态时，通过物质/能量/信息流形成的有序结构 |
